## 1. Цель программы

Программа проверяет, можно ли выдать клиенту автомобиль в аренду, и считает, сколько будет стоить аренда.

## 2. Входные данные

Все семь значений вводятся **одной строкой через пробел** в таком порядке:
`days distance category age experience missing_fuel insurance`

| Вход | Тип | Что означает | Допустимо (моё ограничение) | Почему так |
|---|---|---|---|---|
| days | int | на сколько дней берём машину | 1 … 365 | меньше суток аренды не бывает, больше года — это уже не аренда |
| distance | double | пробег, км | 0 … 100000 | пробег не может быть отрицательным |
| category | int | класс автомобиля | 1, 2, 3 | других тарифов нет |
| age | int | возраст водителя, лет | 16 … 100 | разумный возраст; 16–20 специально разрешены, чтобы можно было проверить правило DENIED |
| experience | int | водительский стаж, лет | 0 … age − 16 | стаж не может быть больше, чем прошло лет с минимального возраста получения прав |
| missing_fuel | double | сколько топлива не долили, л | 0 … 100 | недолив не бывает отрицательным и не больше бака |
| insurance | int | взята ли страховка | 0 или 1 | это просто флаг «да/нет» |

Если хоть одно значение вне диапазона, программа печатает понятное сообщение об ошибке и завершается с кодом 1. Если введены не числа — «Ошибка ввода.» и тоже код 1.

## 3. Результаты

Программа выводит (в BYN, 2 знака после запятой): базовую стоимость `base`, надбавку молодому водителю `young_fee`, плату за топливо `fuel_fee`, плату за страховку `insurance_fee`, итог `total` и **статус** аренды.

## 4. Формулы

- суточный тариф `daily_rate`: категория 1 → 70, 2 → 110, 3 → 180 BYN
- `base = days · daily_rate + distance · 0,25`
- `young_fee = 0,15 · base`, если `age < 25`, иначе 0
- `fuel_fee = missing_fuel · 2,2`
- `insurance_fee = 18 · days · insurance`
- `total = base + young_fee + fuel_fee + insurance_fee`

Деления в программе нет, поэтому деления на ноль возникнуть не может.

## 5. Правила статуса

Проверяются **сверху вниз**, срабатывает первое подходящее:

1. **DENIED** — если `age < 21` или `experience < 1`;
2. **HIGH_DEPOSIT** — если `category = 3` и `insurance = 0`;
3. **FUEL_CHARGE** — если `missing_fuel > 0`;
4. **ACCEPTED** — во всех остальных случаях.

**Замечание:** при статусе DENIED суммы всё равно выводятся. Это сделано намеренно — чтобы клиент видел, сколько стоила бы аренда. Если нужно скрывать суммы при отказе, это меняется одной строкой в `main`.

## 6. Проект функций и таблица контрактов

| Функция | За что отвечает | Параметры и допустимые значения | Результат | Побочные эффекты |
|---|---|---|---|---|
| `get_daily_rate` | Возвращает суточный тариф по категории автомобиля. | category ∈ {1, 2, 3} | double: 70 / 110 / 180; 0 для недопустимой категории | нет |
| `calc_base` | Считает базовую стоимость аренды по дням и пробегу. | days ≥ 1; daily_rate > 0; distance ≥ 0 | double: days·daily_rate + distance·0,25 | нет |
| `calc_young_fee` | Считает надбавку для водителя младше 25 лет. | age ≥ 16; base ≥ 0 | double: 0,15·base при age < 25, иначе 0 | нет |
| `calc_fuel_fee` | Считает плату за недостающее топливо. | 0 ≤ missing_fuel ≤ 100 | double: missing_fuel·2,2 | нет |
| `calc_insurance_fee` | Считает плату за страховку за весь срок. | days ≥ 1; insurance ∈ {0, 1} | double: 18·days·insurance | нет |
| `get_status` | Определяет итоговый статус аренды по приоритету правил. | age, experience, category, insurance, missing_fuel — уже прошедшие проверку | int: 0 DENIED, 1 HIGH_DEPOSIT, 2 FUEL_CHARGE, 3 ACCEPTED | нет |
| `is_input_valid` | Проверяет, что все входные данные лежат в допустимых диапазонах. | любые значения после успешного scanf | int: 1 — данные корректны, 0 — нет | печатает сообщение о первой найденной ошибке |
| `print_status` | Печатает название статуса по его коду. | status ∈ {0, 1, 2, 3} | нет (void) | вывод на экран |
| `print_report` | Печатает все суммы и статус. | суммы ≥ 0; status ∈ {0…3} | нет (void) | вывод на экран |
| `print_age_scenario` | Пересчитывает надбавку, итог и статус для другого возраста и печатает строку сценария (уровень 8). | scenario_age 16…100; остальные значения уже посчитаны в main | нет (void) | вывод на экран |
| `calc_young_fee_mutant` | Испорченная копия `calc_young_fee` (`<=` вместо `<`) только для мутационного теста (уровень 10). | как у `calc_young_fee` | double | нет; в основном расчёте не вызывается |
| `main` | Организует сценарий: ввод → проверка → расчёт → отчёт → сценарии → самопроверка. | — | 0 — успех, 1 — ошибка ввода | ввод с клавиатуры, вызов функций вывода |

### Почему функции разбиты именно так

- **Каждая формула записана ровно в одном месте.** Тариф есть только в `get_daily_rate`, коэффициент 0,15 — только в `calc_young_fee` и т. д. Если поменяется тариф, править надо одну функцию.
- **Решение отделено от печати.** `get_status` только возвращает код и ничего не печатает, а `print_status` только печатает. Поэтому правило приоритета можно проверить простым вызовом функции, не запуская всю программу.
- **Расчётные функции не общаются с пользователем.** Всё получают через параметры и возвращают результат, глобальных переменных нет.
- **Почему `total` не вынесен в функцию:** это просто сумма уже посчитанных частей, своего правила там нет. Отдельная функция только повторила бы длинный список параметров.
- **Почему тариф отделён от `calc_base`:** тариф — это выбор по таблице, а base — арифметика. Раздельно их проще проверять.
- **Почему проверка ввода — одна функция, а не семь:** у всех проверок одна задача — «допустимы ли данные», и вызываются они один раз в одном месте.

**Какое дублирование предотвращено.** В сценариях по возрасту (уровень 8) `print_age_scenario` не пишет формулы заново, а вызывает те же `calc_young_fee` и `get_status`, что и основной расчёт. Самопроверка (уровень 9) тоже вызывает настоящие функции. Значит, если формула изменится, она изменится сразу везде, и расхождения между «основным» расчётом, сценариями и тестами быть не может. Печать статуса тоже одна — `print_status` используется и в отчёте, и в сценариях.

**Функции без побочных эффектов:** `get_daily_rate`, `calc_base`, `calc_young_fee`, `calc_fuel_fee`, `calc_insurance_fee`, `get_status`. Их удобно тестировать: результат зависит только от параметров, один и тот же вызов всегда даёт одно и то же, и для проверки не нужно ничего вводить с клавиатуры.

## 13. Уровень 7 — независимая проверка функций

**Три функции, проверенные отдельно от программы:**
- `calc_young_fee` — вызовы с age = 24 и age = 25 (15.0 и 0.0) проверяют строгую границу `< 25`;
- `calc_insurance_fee` — вызовы с insurance = 0 и 1 (0.0 и 54.0) проверяют, что страховка считается только если она взята;
- `get_status` — три вызова проверяют приоритет правил: DENIED важнее остальных, HIGH_DEPOSIT важнее FUEL_CHARGE, и ACCEPTED когда ничего не сработало.

**Предотвращённое дублирование:** формулы надбавки и статуса существуют только в одном месте. Сценарии по возрасту и самопроверка вызывают те же функции, что и основной расчёт, а не копируют формулы.

**Функции без побочных эффектов:** `get_daily_rate`, `calc_base`, `calc_young_fee`, `calc_fuel_fee`, `calc_insurance_fee`, `get_status` — ничего не печатают и не читают, только считают по параметрам. Поэтому их можно проверять прямо в коде, как в самопроверке.

## 14. Уровень 8 — сценарии по параметру «возраст»

**Параметр:** возраст водителя `age`. Он участвует сразу в двух правилах — в надбавке (порог 25) и в статусе (порог 21), поэтому на нём лучше всего видно, как меняется результат.

**Сценарии:** возраст из ввода (в контрольном тесте 23), **20** и **26**.

**Почему такой шаг:** 23 лежит между двумя порогами. Если уйти до 20 — пересекаем порог 21 (меняется статус). Если подняться до 26 — пересекаем порог 25 (пропадает надбавка). Так каждый сценарий показывает срабатывание ровно одного правила.

**Допущение:** в сценариях меняется только возраст, стаж и все остальные данные остаются как во вводе.

**Фактический вывод программы** для контрольного теста `3 200 2 23 2 5 1`:

```

Возраст 23: надбавка 57.00, итого 502.00, статус FUEL_CHARGE
Возраст 20: надбавка 57.00, итого 502.00, статус DENIED
Возраст 26: надбавка 0.00, итого 445.00, статус FUEL_CHARGE
```

**Что изменилось и почему:**
- **20 лет:** итог не изменился (502.00), потому что 20 < 25 и надбавка остаётся. Зато статус стал **DENIED**, потому что 20 < 21 — водителю отказывают.
- **26 лет:** 26 ≥ 25, поэтому надбавка 0, и итог уменьшился на 57.00 — до **445.00**. Статус остался FUEL_CHARGE, потому что возраст подходит, а недолив 5 л всё ещё есть.

## 15. Уровень 9 — самопроверка (6 свойств)

| № | Свойство | Что проверяет | Почему характерно для задачи |
|---|---|---|---|
| 1 | с 25 лет надбавки нет | `calc_young_fee(25, 100) == 0` | граница `< 25` — самое лёгкое место ошибиться (`<=` вместо `<`) |
| 2 | в 24 года надбавка равна 15 % от base | `calc_young_fee(24, 100)` в интервале 14.99…15.01 | проверяет и сам коэффициент 0,15, и то, что надбавка включается ниже порога |
| 3 | без страховки плата за неё 0 | `calc_insurance_fee(10, 0) == 0` | страховка — флаг, при 0 она не должна ничего добавлять |
| 4 | DENIED имеет высший приоритет | `get_status(20, 1, 3, 0, 5.0) == 0` | здесь верны все три правила сразу, и должен победить отказ |
| 5 | HIGH_DEPOSIT важнее FUEL_CHARGE | `get_status(30, 5, 3, 0, 5.0) == 1` | проверяет порядок второго и третьего правила |
| 6 | чем выше категория, тем дороже сутки | `get_daily_rate(1) < (2) < (3)` | ловит перепутанные тарифы |

Фактический вывод — все 6 строк PASS:

```
Самопроверка:
PASS: с 25 лет надбавки нет
PASS: в 24 года надбавка равна 15% от base
PASS: без страховки плата за неё равна 0
PASS: DENIED имеет высший приоритет
PASS: HIGH_DEPOSIT важнее FUEL_CHARGE
PASS: чем выше категория, тем дороже сутки
```

**Почему дробное сравнение через интервал 14.99–15.01.** Числа типа double хранятся в компьютере приблизительно: 0,15 нельзя записать в двоичном виде точно. Для 0,15 · 100 сейчас случайно получается ровно 15, но при другом base или другом коэффициенте результат может отличаться от «красивого» числа в последних знаках (например, 0,1 + 0,2 даёт 0.30000000000000004). Сравнение через `==` тогда дало бы ложный FAIL. Поэтому проверяем, что результат «достаточно близко» к 15. А сравнение с нулём (`== 0.0`) безопасно, потому что функция в этих случаях возвращает ровно `0.0`, без вычислений.

## 16. Уровень 10 — мутационный тест

**Мутант:** `calc_young_fee_mutant` — копия `calc_young_fee`, в которой `age < 25` заменено на `age <= 25`. В основном расчёте мутант не используется, его вызывает только мутационный тест.

**Какое свойство должно нарушиться (указано заранее):** свойство 1 «с 25 лет надбавки нет». У мутанта в 25 лет надбавка ещё есть.

**Фактический вывод программы:**

```
Мутационный тест (calc_young_fee с <= вместо <):
Мутант при age = 25 вернул 15.00 вместо 0.00
Мутация обнаружена: свойство «с 25 лет надбавки нет» нарушено
```

**Вывод:** мутанта ловит только тест **ровно на границе age = 25**. Тест с age = 24 его бы не поймал: и правильная функция, и мутант при 24 годах возвращают 15.00. Это показывает, зачем нужны тесты точно на границе, а не просто «где-то рядом».

## 17. Вывод о декомпозиции

Разбиение на маленькие функции, где каждая отвечает за одно правило, сделало программу понятнее: по названию функции сразу видно, что она считает. Каждая формула записана один раз, поэтому основной расчёт, сценарии по возрасту и самопроверка гарантированно используют одни и те же правила. Отделение расчёта (`get_status`) от печати (`print_status`) позволило проверять логику прямо в коде, без ввода с клавиатуры. Благодаря этому получилось сделать самопроверку и мутационный тест, который показал, что граничный тест age = 25 действительно ловит типичную ошибку. Главный минус — у некоторых функций (например, `print_age_scenario`) длинный список параметров, но это цена отказа от глобальных переменных.
